# Discord Quest Runner

![Node.js 20+](https://img.shields.io/badge/node-%E2%89%A520-43853d)
![license MIT](https://img.shields.io/badge/license-MIT-blue)
![dependencies 0](https://img.shields.io/badge/dependencies-0-brightgreen)

Локальная программа, которая закрывает квесты Discord без запуска игр. Она читает список квестов через те же запросы, что и десктопный клиент, принимает задания, отправляет прогресс и показывает состояние в браузерном дашборде. Всё работает на твоей машине: токен и настройки лежат в файле рядом, наружу уходят только запросы к `discord.com`.

> **Важно.** Автоматизация квестов нарушает правила Discord. В 2026 году за это выдают Account Standing violation и блокируют раздел квестов на 10–15 дней, иногда вместе с ним страдает весь аккаунт. Рандомные интервалы и паузы делают поведение менее заметным, но риск не убирают. Если аккаунт ценный, лучше не запускать.

## Как пользоваться

Нужны Windows 10/11 и Node.js 20 или новее. Зависимостей нет, `npm install` не нужен.

1. Запусти `start.bat` (или `npm start` в папке проекта).
2. Откроется дашборд `http://127.0.0.1:4780`.
3. В «Настройках» вставь свой user-токен Discord и сохрани.
4. Нажми «Проверить токен» — должны появиться ник и число квестов.
5. Отметь нужные задания галочками и нажми «Старт».

После запуска браузер можно закрыть: сессия живёт в процессе программы. Окно консоли закрывать нельзя, вместе с ним остановится раннер.

Если приложение уже запущено, повторный старт не поднимет вторую копию — просто откроет дашборд.

### Где взять токен

1. Открой Discord в браузере и войди в аккаунт.
2. `Ctrl+Shift+I` → вкладка **Application** → **Local Storage** → `https://discord.com`.
3. Найди ключ `token` и скопируй значение целиком.

Это должен быть user-токен (длинная строка), а не bot-токен из Developer Portal. В новых сборках Discord поле `token` иногда скрыто, пока открыт DevTools. Тогда его можно достать из консоли:

```js
let w = webpackChunkdiscord_app.push([[Symbol()], {}, e => e]); webpackChunkdiscord_app.pop();
let out = new Set();
for (let id in w.c) {
  let ex = w.c[id] && w.c[id].exports;
  for (let obj of [ex, ex && ex.default]) {
    if (obj && typeof obj.getToken === 'function') {
      try {
        let t = obj.getToken();
        if (typeof t === 'string' && t.length > 30) out.add(t);
      } catch {}
    }
  }
}
copy([...out][0]);
```

Токен даёт полный доступ к аккаунту. Не отправляй его никому и не выкладывай скриншоты с ним. В приложении он хранится открытым текстом в `config.json`; если файл куда-то утёк — смени пароль, старый токен после этого перестанет работать.

## Как идёт работа

Квесты выполняются по очереди, по одному. Между ними пауза 2–7 минут, чтобы сессия не выглядела как конвейер. Прогресс нельзя ускорить: Discord начисляет его по реальному времени и принимает не больше двух минут за один heartbeat. Поэтому квест «играть 15 минут» идёт примерно 15 минут.

Игровые квесты закрываются heartbeat-запросами с `application_id` игры. Видео — запросами `video-progress` в темпе просмотра. По достижении цели раннер «переигрывает» ещё немного и закрывает сессию через `terminal: true`, как это делает клиент при выходе из игры.

Награды появляются в Discord → **Настройки → Подарки**. Автозабор можно включить в настройках (`autoClaim`), но Discord может запросить капчу — тогда награда просто останется в «Подарках».

## Дашборд

- **Карточки квестов** — игра, тип задания, прогресс, срок и статус (не принят / принят / выполнен).
- **Галочки** — что брать в текущую сессию. Истёкшие, выполненные и неподдерживаемые задания выключены.
- **Старт** — принимает выбранные квесты, если они ещё не приняты, и запускает очередь.
- **Стоп** — мягко останавливает: текущий heartbeat закрывается `terminal: true`.
- **Лог** — прогресс, паузы и ошибки человеческим языком, без отладочного шума.

Клиент Discord обновляет прогресс с задержкой. Если цифры в приложении уже выросли, а в Discord ещё нет — обнови страницу квестов.

## Какие квесты поддерживаются

| Тип | Статус | Чем закрывается |
|---|---|---|
| `PLAY_ON_DESKTOP`, `PLAY_ON_DESKTOP_V2` | работает | heartbeat с `application_id` |
| `WATCH_VIDEO`, `WATCH_VIDEO_ON_MOBILE` | работает | `video-progress` |
| `STREAM_ON_DESKTOP` | нет | нужен реальный стрим в голосовом канале и зритель |
| `PLAY_ACTIVITY` | нет | нужен голосовой канал с запущенной активностью |
| `PLAY_ON_XBOX`, `PLAY_ON_PLAYSTATION` | нет | проверяется на консоли |
| `ACHIEVEMENT_*` | нет | достижение выдаёт игра или бэкенд активности |

Неподдерживаемые квесты видны в списке с причиной, но не запускаются. Врать в них нечем.

## Как это работает

Официального API квестов нет. Клиент Discord ходит в недокументированные ручки, они же использует приложение:

```
GET  /quests/@me                  список квестов и прогресс
POST /quests/{id}/enroll          «Принять задание»
POST /quests/{id}/heartbeat       «Игра запущена»  { application_id, terminal }
POST /quests/{id}/video-progress  «Видео смотрится» { timestamp }
POST /quests/{id}/claim-reward    забрать награду
```

Цикл выглядит так:

1. `GET /quests/@me` — нормализация заданий: тип, цель, прогресс, `application_id`, сроки.
2. Отбор активных, невыполненных и поддерживаемых.
3. `enroll` для тех, что ещё не приняты.
4. Heartbeat с рандомными интервалами, затем «переигрывание» и `terminal: true`.
5. Видео — `video-progress` с шагом 7–9,5 секунды, без обгона реального времени.
6. Попытка `claim-reward`, если включён `autoClaim`.

Сервер сам считает прогресс по времени между heartbeat (максимум 120 секунд за раз) и ставит `completed_at`, когда значение дошло до цели.

Для запросов нужен `User-Agent` с `Electron/…` и заголовок `X-Super-Properties` с согласованными версиями клиента, иначе будет 401. Это уже прописано в `src/discord.js`. Поле `executable_fingerprint` не отправляется вообще: это нативная аттестация бинарника, подделать её нельзя, а пустое значение — нормальное состояние клиента.

## Настройки

При первом запуске создаётся `config.json` из `config.example.json`. Часть параметров можно менять в дашборде, остальное — руками в файле.

### `engine`

| Параметр | Значение |
|---|---|
| `autoStart` | запускать выбранные квесты сразу при старте программы |
| `autoEnroll` | принимать задания автоматически |
| `autoClaim` | пытаться забрать награду после выполнения |
| `heartbeatSeconds` | `[min, max]` интервал heartbeat, секунды |
| `videoTickMs` | `[min, max]` шаг видео-прогресса, миллисекунды |
| `overshootSeconds` | `[min, max]` сколько «переиграть» после цели |
| `startDelaySeconds` | `[min, max]` пауза перед началом квеста |
| `closeDelaySeconds` | `[min, max]` пауза перед `terminal: true` |
| `gapMinutes` | `[min, max]` пауза между квестами |
| `pauseChance`, `pauseSeconds` | вероятность и длина случайной «залипки» |
| `maxQuestsPerSession` | сколько квестов брать за один запуск |
| `keepAwake` | не давать компьютеру уснуть во время сессии |

### `web`

| Параметр | Значение |
|---|---|
| `port` | порт дашборда, по умолчанию 4780; если занят, берётся следующий |
| `openBrowser` | открывать браузер при запуске |

### `network`

| Параметр | Значение |
|---|---|
| `proxy` | HTTP(S)-прокси, например `http://127.0.0.1:10809`. Пусто — определить автоматически |

Node не использует системный прокси без отдельного флага, поэтому приложение при старте ищет прокси в таком порядке: `network.proxy` → `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` → настройки Windows. Найденный адрес применяется перезапуском процесса с `NODE_USE_ENV_PROXY=1`; `127.0.0.1`, `localhost` и `::1` идут напрямую. Поддерживаются только HTTP/HTTPS-прокси (SOCKS нет). После изменения `network.proxy` нужен перезапуск. Автоопределение отключается переменной `QUEST_RUNNER_NO_PROXY=1`.

### `discord`

| Параметр | Значение |
|---|---|
| `token` | user-токен; можно задать через `DISCORD_TOKEN` |
| `apiVersion` | версия API, по умолчанию 10 |

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Токен не принят» (401) | скопирован bot-токен вместо user-токена, либо токен умер после смены пароля — возьми новый |
| «Сеть: fetch failed», хотя интернет есть | Discord недоступен напрямую. Проверь прокси/VPN; приложение подхватывает системный прокси, но адрес можно вписать в `network.proxy` и перезапустить |
| «Discord отклонил запрос» (403) | раздел квестов ограничен для аккаунта, смотри «Нарушения аккаунта» |
| Квестов 0 | в регионе/аккаунте нет активных квестов либо не нажал «Обновить»; проверь `npm run selftest` |
| Прогресс стоит | смотри лог: heartbeat уходит, но клиент Discord показывает прогресс с задержкой |
| Квест закрылся, награды нет | забери вручную: Настройки → Подарки |
| Кракозябры в консоли | запускай через `start.bat` (там `chcp 65001`) или в Windows Terminal |
| Порт занят | приложение возьмёт следующий; либо задай другой `web.port` |

## Демо без токена

Посмотреть интерфейс и прогнать сессию можно на фальшивом Discord API:

```powershell
npm run demo
```

Поднимается mock-сервер с семью квестами (есть просроченный и неподдерживаемый) и дашборд на `http://127.0.0.1:4781`. Прогресс в демо ускорен: один heartbeat закрывает квест.

## Технологический стек

- **Node.js 20+**, ESM. Внешних зависимостей ноль: HTTP-клиент и сервер на встроенных модулях, `fetch`, `node:http`, `node:test`. Меньше пакетов — меньше обновлений и никаких сюрпризов в цепочке поставок.
- **Ванильные HTML, CSS и JS** для дашборда. Без React, сборщика и транспиляции: страницу можно открыть и починить без установки тулчейна.
- **Недокументированный API Discord** — те же ручки, что у десктопного клиента.
- **`node:test`** и собственный mock Discord для end-to-end проверок движка.
- **PowerShell** для режима «не спать» и **реестр Windows** для поиска системного прокси.

## Структура

```
src/
  index.js        CLI: run, list, selftest
  config.js       config.json, значения по умолчанию, маскирование токена
  proxy.js        поиск прокси и перезапуск с NODE_USE_ENV_PROXY
  discord.js      клиент API: заголовки клиента, retry, rate limit
  quests.js       нормализация квестов, типы, причины неподдержки
  engine.js       очередь, enroll, heartbeat/video, claim, остановка
  timing.js       случайные задержки и паузы
  server.js       локальный HTTP + JSON API + статика
  keepawake.js    режим «не спать»
  public/         дашборд
scripts/
  demo.mjs        демо на mock-сервере
test/
  тесты + mock-discord.js
```

`config.json` и `data/runner.log` создаются при работе и в git не попадают.

## Чего здесь нет

- Игры не запускаются, процессы в системе не подделываются.
- Память игр не читается, античиты не обходятся.
- Bot-токены не используются, публичного бота здесь нет.
- `executable_fingerprint` не подделывается.
- Гарантий, что Discord не заметит автоматизацию, тоже нет.
